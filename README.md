# auma-project-3

Панель управления технической документацией: по номеру заказа подтягивает
документы с сайта AUMA и складывает их в общее хранилище с фильтрами,
папками и владельцами файлов.

## Что умеет

- **Регистрация и вход** по email с паролем.
- **Загрузить характеристики** — по номеру заказа скачивает Technical Data Sheet
  с сайта AUMA. Формат выбирается: `web` (htm) или `pdf`.
- **Разбивка по позициям.** Заказ может состоять из нескольких позиций
  (`Pos. 1.0`, `Pos. 2.0` …). Тогда полный файл получает в колонке Article
  все изделия через подчёркивание (`SAEX-07.2_ACEXC-01.2`), а **каждая
  позиция сохраняется ещё и отдельным документом** со своим артикулом
  и попадает в свою папку. Работает одинаково для `pdf` и `web`.
- **Загрузить схему пдкл.** — по номеру заказа получает схему подключения (PDF)
  и попутно определяет артикул изделия.
- **Таблица документов**: File, Data Uploaded, Article, Order, File Size,
  File Owner, Action. **Фильтр есть у каждой колонки.**
- **Две группы в меню**:
  - **Привод** — папки SA, SAEx, SQ, SQEx;
  - **Блоки управления** — папки AC, ACExC, AM, AMExC.
  Группа сворачивается, а при раскрытии показывает документы всех своих папок.
- **Раскладка по папкам по артикулу**: `SQEX-07.2` попадает в `SQEx`,
  `SAEX-10.2` — в `SAEx`, `AM-01.1` — в `AM`. Дерево описано в
  `app/catalog.php`; там же достаточно дописать новую папку.
- **Звезда** — в избранное, **три точки** — меню «Отправить на почту» и «Удалить файл».
- Корзина, счётчик хранилища.

## Технологии

- PHP 8.5 + MySQL 8.4, nginx — без единой внешней библиотеки и без сборки фронтенда.
- Фронтенд: чистые HTML/CSS/JS, стили сняты с макета.

## Структура

```
app/            PHP: конфиг, БД, авторизация, интеграция с AUMA, API
  auma.php      разбор форм AUMA (характеристики и схемы)
  catalog.php   дерево групп и папок — одно место для всей структуры
  api.php       JSON API
  views/        шаблоны страниц
public/         веб-корень (index.php, assets, uploads)
sql/schema.sql  схема базы
deploy/         установка, настройка и обслуживание
```

## Установка на чистый сервер

```bash
# 1. окружение
bash deploy/install-server.sh

# 2. залить файлы проекта в /var/www/auma

# 3. настроить сайт
bash deploy/setup-site.sh
```

Пароль базы генерируется автоматически и лежит в `/root/.auma-db-pass`;
он же прописывается в `app/config.php`.

## Настройка

`app/config.php` (в репозиторий не попадает, образец — `app/config.sample.php`):

- `db.*` — доступ к MySQL;
- `app.upload_dir` — куда складывать скачанные документы;
- `mail.enabled` — **отправка на почту пока выключена**. Кнопка есть, письмо
  пишется в таблицу `email_log` со статусом `stub`. Когда появятся настройки
  SMTP, достаточно заполнить `mail.*` и включить `enabled`.

## Как устроена интеграция с AUMA

Обе функции AUMA — обычные ASP.NET-формы, разобранные по шагам.

**Характеристики**

1. `GET www4.auma.com/webservices/TechnicalDataSheetPublic/request.aspx?lang=en`
2. `POST TypeDdl=Order, numberTB=<заказ>, LanguageDdl=E, FormatDdl=htm|pdf`
3. в ответе ссылка `.../AumaWebService/Data/TDS<заказ>_en-<метка>.<ext>`
4. скачивание

**Схема подключения**

1. `GET www4.auma.com/Schaltplan/AuftragsForm.aspx?Lang=en`
2. `POST OrderOrSerialNo=<заказ>, Button1=execute` — в ответе таблица изделия
   с артикулом
3. `POST RequestBttn=Request wiring diagram` — редирект
   `Redirector.aspx?goto=temp%2fTPA....pdf`
4. скачивание PDF

> **Важно.** AUMA отдаёт `HTTP 500`, если запрос не похож на браузерный.
> Заголовки `Accept`, `Accept-Language`, `Upgrade-Insecure-Requests` и
> `Sec-Fetch-*` в `app/auma.php` обязательны — без них формы «не работают».

## Разбивка по позициям

Позиция заказа начинается пометкой `Pos. N.0`, под которой стоит её `Article`.
Когда позиций несколько, сохраняется и полный файл, и **каждая позиция
отдельным документом** — включая первую. Артикулы всех позиций склеиваются
через `_` и пишутся в Article полного файла.

**PDF** (`pdf_split_positions`) — нужны `pdftotext` (пакет `poppler-utils`)
и `qpdf`, их ставит `deploy/install-server.sh`:

1. `pdftotext -layout` разбирает PDF по страницам;
2. на каждой странице ищется `Pos. N.0` и её `Article`;
3. позиция занимает страницы со своей пометки **до страницы со следующей
   пометкой включительно**; последняя — до конца файла;
4. страницы вырезаются через `qpdf --empty --pages`.

> **Почему границы перекрываются.** Таблица позиции часто переходит на
> следующую страницу: например, у заказа 13497303 на странице 3 сначала
> идёт продолжение ACEXC-01.2 и только потом начинается Pos. 3.0.
> Разрезать страницу PDF пополам нельзя, поэтому если резать по страницу
> раньше, хвост таблицы потеряется. Выбран вариант, при котором ничего
> не теряется: файл позиции захватывает и страницу, где начинается
> следующая. В итоге соседние файлы частично перекрываются.

**Web** (`htm_split_positions`) — инструменты не нужны, разметка разбирается
регулярным выражением:

1. позиции ищутся по `<b>Pos.N.0</b>`;
2. позиция занимает разметку **от своей пометки до следующей**; последняя —
   до конца документа;
3. для каждой позиции собирается самостоятельный файл: заголовок,
   стиль AUMA и строка заказа берутся из исходного документа.

Здесь границы точные: разметку можно разрезать ровно по пометке,
поэтому файлы не перекрываются.

Если позиция одна или (для PDF) инструментов нет, документ сохраняется
целиком, как раньше.

> **Про AppArmor.** В Ubuntu у `qpdf` есть профиль AppArmor, который
> запрещает читать файлы из `/var/www` и временные файлы без расширения
> `.pdf` — в журнале это видно как `apparmor="DENIED" profile="qpdf"`.
> Поэтому разбор PDF идёт во временном каталоге и только с именами `*.pdf`.
